# Visual project documentation

## Canonical development baseline

Start with `foundation/README.md`.

`foundation/` contains the current synthesized product assumptions, engineering principles, architecture baseline and experiment/validation rules that should guide new development.

Dated files in `../../artifacts/` remain research/evidence/provenance rather than the primary source of current development policy.

## Development operations

- `development_operating_model.md` — agent/delegation/write/build/test operating rules.
- `development_environment_baseline.md` — canonical machine/toolchain baseline.

## Doxa hardware and installation

Start with `hardware/README.md` for tasks involving:

- Doxa electronics;
- USB/display/audio/power hardware;
- driver/firmware packages;
- factory programming;
- installation;
- support diagnostics;
- LLM-assisted setup/support.

The hardware documentation deliberately keeps unverified hardware assumptions separate from the Visual magnifier architecture.

## Agent entry point

Repository agents must follow `../../AGENTS.md`, which references the relevant project documents and establishes precedence.
