## Integrated architecture now running

```text
Windows Graphics Capture source
  -> Windows POI evidence
       -> moving pointer
       -> UIA TextPattern2 caret
       -> UIA TextPattern insertion range
       -> Win32 caret fallback
       -> UIA focus
       -> Win32 focus fallback
  -> freshness + intent arbitration
  -> viewport controller
  -> locator model
  -> D3D11 crop / scale / locator
  -> non-activating second-screen Detail window
```

UI Automation runs on a separate worker thread. The D3D11 renderer is provider-agnostic and receives viewport/locator state.

## Recovery conclusion for first two-screen MVP

Physical evidence supports the following bounded recovery policy for the first MVP:

1. if the active display topology changes while Visual is running, stop safely rather than continuing with potentially stale monitor/capture assumptions;
2. after Windows has restored the desired two-display topology, relaunch Visual;
3. on relaunch, enumerate the current topology and rebuild the capture/render state from current monitor geometry.

This is acceptable for the first two-screen MVP because it is deterministic, avoids frozen/stale rendering, and has now succeeded in a real HDMI disconnect/reconnect cycle.

Automatic in-process hot-plug rebinding remains desirable hardening, but it is not required for first-MVP sign-off unless later task-use evidence shows topology changes are frequent enough to make relaunch materially disruptive.

## Current interpretation

The functional two-screen MVP is now primarily a **usability, compatibility and packaging** problem rather than a feasibility/integration/recovery problem.

Central runtime mechanisms now coexist in one executable with positive physical evidence:

- live WGC/D3D11 Detail;
- pointer, semantic caret and focus evidence;
- layered fallback;
- user-intent arbitration;
- viewport hold/pan/jump policy;
- target locator;
- global zoom/tracking controls;
- exact normal/return state;
- safe real HDMI topology invalidation;
- successful post-reconnect relaunch.

Rough engineering progress toward the defined two-screen MVP: **~80–85%**.
