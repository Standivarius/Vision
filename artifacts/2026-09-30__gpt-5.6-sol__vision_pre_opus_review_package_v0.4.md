## 2. What changed since v0.3

The ZoomText broad feature assessment is now complete.

The research package no longer treats ZoomText as a narrow pointer/caret/focus benchmark. It now covers the current manual-derived feature surface and distinguishes:

- earlier hands-on evidence;
- current installed-state evidence;
- current vendor-documented semantics;
- bounded behavioural uncertainties.

A cross-product synthesis now reconciles ZoomText, SuperNova and current Vision around recurring user problems rather than product menu trees.

The main new architecture/product conclusions carried into review are:

- visual pointer/caret/focus orientation is first-product core rather than cosmetic polish;
- multi-monitor view ownership is an explicit architecture decision;
- per-view visual/enhancement state is core to credible 2–4 monitor behaviour;
- context recovery, pinning and relocation should be treated as one problem family;
- text quality should use a layered/fallback architecture rather than a premature all-or-nothing semantic renderer;
- compatibility/supportability remains a core product obligation despite a smaller visible feature set.

## 3. Current proposed first-product core

For Opus to challenge, not rubber-stamp:

- high-quality magnification;
- pointer/caret/focus tracking;
- predictable viewport movement;
- temporary 1x / locator / overview orientation;
- small strong pointer/caret/focus visual cue presets;
- practical colour/contrast/tint controls;
- coherent 2–4 monitor per-view state;
- explicit view ownership and monitor-boundary policy;
- renderer-quality extension seam;
- persistence, install/update, diagnostics and bounded compatibility;
- contextual help/discoverability.

## 4. Seams to preserve, not launch commitments

- one useful single-monitor contextual/lens/docked geometry;
- pinned context;
- Tethered-like context relocation;
- app-scoped settings;
- clone/standard-view collaboration;
- presentation mode;
- clean-text/simplified reading view;
- non-visual boundary cues.

## 5. Deliberate first-product exclusions

Unless Opus finds contrary evidence:

- Span;
- incumbent-scale geometry/catalogue parity;
- full custom highlight editors;
- full Situation Settings/profile complexity;
- Reader/AppReader/Doc Reader/Line View as product pillars;
- screen-reader/Braille;
- OCR/Finder;
- camera/whiteboard;
- touch;
- Secure Mode/logon parity;
- broad Citrix/RDP/virtual-environment promise.

## 6. Evidence boundary

Hands-on and installed-state evidence is now broad enough for an independent architecture/product review, but several uncertainties remain intentionally visible:

- matched Vision vs ZoomText xFont / SuperNova True Font Office rendering at identical practical zoom;
- ZoomText MultiView hand-off feel;
- ZoomText Tethered View and Live Text View real-task feel;
- SuperNova Mouse Buffer subjective behaviour;
- Hooked Area / Freeze / Tethered task value;
- physical 3/4-monitor usability;
- user preference among full-screen, Context+Detail and contextual/lens views.

Only the Office text-quality question currently appears capable of materially changing the renderer decision before implementation. Opus is explicitly asked to decide whether it must block Stage 1 architecture extraction or can gate a later renderer decision.
