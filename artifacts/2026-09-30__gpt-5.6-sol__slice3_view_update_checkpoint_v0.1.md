## Change

Added `app/src/core/view_update_step.h` and `app/tests/view_update_step_tests.cpp`.

`ViewUpdateStep` now owns the current pure decision sequence:

1. legacy follow-eligibility filtering;
2. ViewController arbitration / viewport decision;
3. locator visibility decision and locator geometry.

Both production runtime and the deterministic ReplayOracle now call the same step.

The step consumes only:

- source geometry
- settings
- evidence values
- time/frequency

It does not sample UIA/Win32, own WGC, call Present or resolve monitor identity.

- acceptance-seed pointer -> viewport mapping
- legacy follow-disabled filtering
- tracking-off viewport hold with selected-target locator behaviour

No pointer-boundary, ownership or overlay/follow policy fix was introduced.

## Architecture checkpoint after Slices 1-3

Current decision/data path is now explicit:

`EvidenceSampler -> EvidenceSnapshot -> ViewUpdateStep -> ViewUpdate/Locator -> Renderer`

Current remaining coupling:

- WGC capture lifetime and rendering scheduling still live in CaptureRunner
- Renderer still owns device/context/swapchain/cached source and Present
- capture callback writes into renderer-owned cached source
- one physical source and one output remain assumed
- topology is still startup-resolved
- active movement ownership is not yet a first-class policy

This is the intended boundary before Slice 4.

## Decision

**Slice 3 is complete.**

The next safe structural operation is Slice 4: separate GPU device domain / CaptureSource / OutputPresenter while preserving one source and one output.
