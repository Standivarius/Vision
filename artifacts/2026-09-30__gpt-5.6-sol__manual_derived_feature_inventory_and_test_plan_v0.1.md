## Classification

- **Core candidate**: plausibly required in focused Vision.
- **Second-layer**: potentially valuable, but not a launch dependency without stronger evidence.
- **Boundary / defer**: outside the initial magnifier-first product or niche enough to postpone.
- **Architecture gate**: could materially alter the planned Vision architecture.

Hands-on status values: `Verified`, `Partially verified`, `Documented only`, `Not applicable to installed edition`.

## Cross-check against current live SuperNova 25.05 menus

The installed Magnifier 25.05 control panel was enumerated directly so the manual-derived list can be checked against the shipping UI. Current menus expose the following additional or more explicit capabilities:

- **File / configuration:** new and edit Situation Settings, Application Settings, Maps and Scripts; import/export application settings, maps, scripts and user settings; save settings; restore defaults.
- **Visual:** magnifier on/off; size; all eight magnifier-view positions/types; the full colour-scheme catalogue; custom colour configuration; highlighting on/off and seven named schemes (Default, Large Red, Large Red with Mouse, Large Blue, Large Blue with Mouse, Large Yellow, Large Yellow with Mouse, Custom); mouse-pointer settings; Doc Reader settings; Hooked Areas; Connect & View; Whiteboard; Multiple Monitors; Visual Advanced Options.
- **Media:** Ask AI for an image file or clipboard image, Face Position, EasyReader, News, Radio Stations and Podcast.
- **General:** Item Finder, notifications, updates/release notes, keyboard settings, hotkeys, control-panel settings, startup preferences, touchscreen settings, feedback settings and advanced options.
- **Help/support:** Windows Explorer help, SuperNova Manual, SuperNova Help, support website, Remote Support, Ask a Question, Report a Bug, feedback, unlock/licensing and About.

This confirms that the live product has materially more breadth than the first basic benchmark. The research should not treat the toolbar buttons as the whole feature surface.

### Specific visual-enhancement features that must be hands-on tested

1. Large Red, Large Red with Mouse, Large Blue, Large Blue with Mouse, Large Yellow, Large Yellow with Mouse.
2. Custom Highlighting settings: determine exact shapes for mouse, text cursor, current word/line and Windows focus; capture examples.
3. Mouse pointer schemes and pointer size independence from magnification.
4. Colour schemes plus custom brightness/contrast/tint/replace-colour controls.
5. Overview Mode, Margin Release and any edge/orientation cues.
6. Hooked Areas and app-specific persistence.
7. Multiple Monitor dialog: Side-by-Side, Mouse Buffer/resistance, Clone, Span, Presentation and per-monitor zoom/colour behaviour.
8. True Font behaviour against Vision at 2x, 3x and 4x in representative applications.
9. Situation Settings and Application Settings: understand whether these are user-facing presets, app-triggered profiles, or both.
10. Doc Reader and Line View as visual-access features even though the initial Vision scope is magnifier-first.

## Manual cross-check additions and corrections

The full 2026 ZoomText User Guide adds several magnifier-relevant capabilities that a toolbar-only review would miss:

- **Tethered View**: contextually brings remote information next to the current point of work. Documented scenarios include Windows Start search, the Excel formula bar and Word Comments. This is strategically important because it solves the same attention-distance problem as Hooked Areas, but dynamically rather than as a permanently pinned region.
- **Finder**: search/skim/navigation across documents, web pages and email. This is a workflow aid rather than a core magnification primitive.
- **ZoomText Camera**: printed-document/object magnification using a webcam. Niche for the first office-focused Vision scope.
- **OCR**: inaccessible PDFs/images/screen regions can be converted into text and opened in a visual reading environment. Valuable, but it pushes Vision toward reading/document-transformation territory.
- **Touch support**: touch icon and gestures. Defer unless Vision targets touchscreen hardware.
- **Windows Logon / Secure Mode**: magnification and, where available, reading support on logon and secure prompts. Commercially important for some managed-workplace use cases but expensive to qualify safely.
- **Quick Access / command-key infrastructure**: the manual treats efficient command access as a substantial product surface. Vision should keep shortcuts discoverable and customizable without copying incumbent complexity.
- **Support/diagnostic tooling**: System Information, Support Tool and Fix-It commands are part of the maintained product. This reinforces that supportability is a product capability, not merely back-office engineering.

Two ZoomText visual features deserve higher priority than in the earlier research:

1. **Tethered View** should be compared directly with SuperNova Hooked Areas and with Vision's current Context/Detail concept. It may represent a high-value pattern: bring distant context to the user's locus of attention instead of making the user pan across the magnified desktop.
2. **Live Text View** is a separate high-contrast text strip that can follow typing/navigation, mouse text or reading tools. It is especially relevant if xFont/semantic text quality is difficult to reproduce; a focused text view may deliver some of the user value with a different implementation path.

The SuperNova QRG also confirms product-operation features that matter to adoption:
- hotkey access to the magnifier, view cycling, colour toggle, Line View and monitor switching;
- layered hotkeys as an alternate discoverability path;
- CAPS+F1 context help inside applications;
- touch gestures in supported editions.

These are not all reasons to add features to Vision. They are evidence that mature low-vision products invest heavily in **orientation, discoverability and rapid recovery**, not only magnification.
