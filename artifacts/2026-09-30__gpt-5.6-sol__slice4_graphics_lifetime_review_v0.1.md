# Vision Structural Slice 4 review v0.1

**Date:** 2026-09-30
**Result:** PASS

## Structural result
The current single-output runtime now has explicit graphics/capture/presentation lifetime boundaries inside the existing translation unit:

- `GpuDeviceDomain`: owns one D3D11 device, immediate context, WinRT device and the domain-level immediate-context mutex.
- `CaptureSource`: owns the latest copied capture texture and monotonic frame generation.
- `CaptureFrameSnapshot`: value snapshot of capture texture reference + generation.
- `OutputPresenter`: owns the HWND swapchain/render target and `Present`.
- `Renderer`: owns shader/render resources and renders a supplied capture snapshot into a supplied output presenter.
- WGC `CaptureRunner` uses the GPU domain directly and publishes frames to CaptureSource.

The old renderer-owned `cachedSource_`, `renderer_.winrt_device()`, `renderer_.cache_source()`, `render_cached()` and renderer-local D3D mutex paths are gone.

## Synchronisation
The single D3D11 immediate context is protected at the GPU-domain level. Capture `CopyResource` and rendering commands share that lock. The lock is explicitly released before `OutputPresenter::present()`, so a blocking/slow Present no longer holds the shared immediate-context mutex.

This does not yet prove two-output pacing isolation; that remains the dedicated fan-out experiment/slice.

## Generation evidence
CaptureSource increments a monotonic frame generation after each published frame. Render snapshots carry the generation. Runtime detects generation regression as an error and emits `first_render_source_generation` when rendering begins from a real captured generation.

The accepted physical run contains `first_render_source_generation` and no `capture_frame_generation_regressed`.
