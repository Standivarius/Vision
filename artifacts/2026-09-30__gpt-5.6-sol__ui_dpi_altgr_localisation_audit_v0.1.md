# Vision UI / DPI / AltGr / localisation audit v0.1

Date: 2026-09-30
GitHub: #20
Status: AUDIT COMPLETE / IMPLEMENTATION NEXT

## Observed repository facts

- The application and diagnostics explicitly request Per-Monitor V2 DPI awareness.
- Settings and Help use fixed initial dimensions and hard-coded pixel layouts.
- Settings/Help/Hint have no WM_DPICHANGED handling and no GetDpiForWindow-based layout/font scaling.
- Settings uses caption-text lookup with FindWindowExW for several layout targets. This is fragile under localisation and duplicate captions.
- User-visible Settings, Help, menu, hint and error strings are hard-coded directly in C++ rather than behind stable resource/string keys.
- Persistent settings/diagnostic identifiers are already language-neutral enough to remain separate from display strings.
- Global hotkeys use MOD_CONTROL | MOD_ALT | MOD_NOREPEAT for 0/1/2/3/4/Q/S/T/H.

## Deterministic AltGr collision probe

The current Windows installation only has en-US configured, so a manual machine test would not qualify AltGr behaviour. A disposable thread-local probe loaded installed Windows keyboard-layout DLLs and used VkKeyScanEx to identify characters produced by Ctrl+Alt (AltGr) on Vision hotkey keys. It made no permanent keyboard-layout change.

Romanian (Programmers), KLID 00020418, collisions include:

- AltGr+Q -> â
- AltGr+S -> ș
- AltGr+T -> ț
- AltGr+0/1/2/3/4 -> dead/diacritic characters

German, KLID 00000407, collisions include:

- AltGr+Q -> @
- AltGr+0 -> }
- AltGr+2 -> ²
- AltGr+3 -> ³

Conclusion: the current global Ctrl+Alt shortcut family is not localisation-safe. This is a concrete product defect, not merely a theoretical concern.

## Recommended implementation order

1. Remove caption-based layout lookup by storing control HWNDs/IDs directly.
2. Add DPI-aware layout primitives and WM_DPICHANGED handling to Settings and Help; recreate fonts at current window DPI.
3. Introduce a small stable user-visible string catalogue/resource seam without translating yet.
4. Replace the default global Ctrl+Alt shortcut family with a localisation-safe command scheme after a bounded Windows/conflict review; retain commands independently of physical key bindings so shortcuts can later be configurable.
5. Add deterministic tests/diagnostics for command bindings and resource keys.
6. Run UI surface smoke at multiple DPI/text-scale conditions and rerun canonical regression.

## Boundary

Do not rename compatibility identifiers such as visual_app.exe, Standivarius.Visual, Visual settings paths or VISUAL_* environment/registry contracts as part of localisation work.

## Implementation and decision update — 2026-09-30

### DPI/localisation seam implemented

- Settings caption-based layout lookup was removed. Layout now uses stored HWND/control identity, so translating captions cannot break geometry.
- Settings and Help scale initial geometry for the target monitor DPI.
- Both surfaces handle WM_DPICHANGED, accept the Windows-suggested rectangle, rebuild fonts from the current system message font and relayout.
- Both surfaces refresh fonts/layout on WM_SETTINGCHANGE.
- app/src/ui_dpi.h contains the shared DPI/font helper.
- app/src/core/ui_strings.h establishes stable language-neutral keys with English fallback values for Settings and Help.
- ui_strings_tests checks key uniqueness/non-empty values.
- app/src/core/command_bindings.h separates Vision commands from physical global bindings.
- command_bindings_tests checks binding identity/round-trip and explicitly marks the current Ctrl+Alt profile as unsafe for external release.

### Hotkey decision

Do not replace Ctrl+Alt with an arbitrary new chord inside #20.

Evidence:
- Microsoft Windows keyboard UX guidance explicitly says not to use Ctrl+Alt for application shortcuts because some language versions interpret it as AltGr.
- Microsoft RegisterHotKey documentation says Windows-key shortcuts are reserved for the operating system and F12 is permanently reserved for the debugger.
- ZoomText uses a dedicated Caps Lock-oriented command model and layered keys.
- SuperNova supports multiple hotkey sets and also uses Caps Lock/layered commands extensively.

Current decision:
- retain the existing Ctrl+Alt mapping only as an internal-alpha compatibility profile so current regression/harness evidence remains comparable;
- mark that profile not safe for broader external release;
- keep product commands independent of the binding table so a later binding model does not rewrite command behaviour;
- choose the external-alpha shortcut model as a bounded product/accessibility decision, informed by early low-vision/assessor work, rather than silently replacing one conflict-prone global set with another.

Sources reviewed:
- Microsoft, Keyboard - Win32 apps: https://learn.microsoft.com/en-us/windows/win32/uxguide/inter-keyboard
- Microsoft, RegisterHotKey: https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey
- Freedom Scientific, ZoomText User Guide / current command model
- Dolphin, SuperNova Hotkeys / current learning material
