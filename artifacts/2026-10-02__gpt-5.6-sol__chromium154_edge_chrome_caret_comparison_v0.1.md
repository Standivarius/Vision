# Vision Chromium 154 caret compatibility comparison v0.1

Date: 2026-10-02
Host: MARIUS-DELL
Windows: 10.0.26200
Scope: deterministic local text-editing fixture; UIA/Win32 caret-provider evidence only.

## Purpose

Determine whether the current Edge 154 caret regression is a generic Chromium 154 problem, a provider-mode problem, or an Edge-specific compatibility exception.

No production Vision code was changed for this comparison.

## Conclusion

The current failure is not a generic Chromium 154 failure. Chrome 154 on the same host exposes a strong ordinary TextPattern caret path while Edge 154 does not.

The current evidence also rejects a simple Edge launch/provider-flag fix: forcing accessibility, forcing the native UIA provider, or disabling that provider all remain severely degraded.

Therefore:

- keep the current Edge 154 row as a Known issue;
- add Chrome 154 deterministic editing as Bounded-good for the exercised provider path;
- do not add Edge-specific production code merely to recover this isolated provider regression;
- Vision should continue its layered-provider behaviour and degrade to focus/pointer evidence when no reliable caret rectangle exists;
- a future Edge version materially changes this row and should be retested.

This is browser/provider compatibility evidence, not a rendering-quality conclusion and not coverage of arbitrary rich web editors.
