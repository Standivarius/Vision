# Incumbent feature discovery and value matrix v0.1

**Date:** 2026-09-30
**Status:** pre-Opus hands-on + official-source synthesis

## Purpose

This expands the earlier benchmark work beyond pointer/caret/focus tracking. The question is not merely whether Vision can follow the user; it is which incumbent features create meaningful low-vision value, which are mostly breadth/legacy complexity, and which Vision can capture cheaply because related mechanisms already exist.

## Evidence basis

- live SuperNova Magnifier 25.05 install on Marius-DELL;
- live SuperNova control-panel/menu hierarchy extracted from the running application;
- deterministic pointer/caret/focus/cross-monitor runs against SuperNova;
- hands-on ZoomText 2026 runs completed earlier;
- current Dolphin/Freedom Scientific product documentation;
- current Vision codebase and existing acceptance evidence.

## Key correction from hands-on work

The first comparison plan over-weighted tracking benchmarks. That would have missed a commercially and ergonomically important class of **orientation / visibility aids**: coloured rectangles, arrows/pointers, line/caret/focus emphasis, large pointer schemes, overview/context aids and pinned reference regions.

SuperNova treats these as first-class magnifier functionality, not decoration. Vision already has primitive locator/highlight mechanisms, so some of this value may be comparatively inexpensive to add.

## Feature/value implications

| Feature family | What the incumbent is solving | Current Vision position | Likely effort from current Vision | Working recommendation |
|---|---|---|---|---|
| Pointer / caret / focus tracking | Keep the active object inside the useful magnified area | Already implemented with separate evidence providers and arbitration | Compatibility-heavy rather than greenfield | **Core**; quality/compatibility remains more important than adding options |
| Focus/caret/mouse highlighting | Make the active location visually obvious even when tracking is technically correct | Basic locators/highlights exist | Low to moderate | **Raise priority**. Expand into a small set of strong schemes rather than incumbent-scale customisation |
| Large red/yellow/blue focus schemes | Rapid orientation; visible to user, trainer or sighted colleague | No equivalent preset family | Low | **High-value quick win candidate** |
| Mouse pointer schemes | Prevent pointer loss without obscuring magnified text | Pointer locator exists; pointer-image replacement not implemented | Low-moderate for halo/shape; higher for full pointer replacement catalogue | **Core subset**, not 200-pointer parity |
| Colour schemes | Reduce glare, improve contrast, accommodate individual colour needs | Normal / contrast / invert / grayscale | Low-moderate | **Core**, add user-configurable brightness/contrast/tint and a few strong presets before dozens of named schemes |
| Text smoothing / True Fonts / xFont | Keep text legible at higher magnification | Raster crop/scale | Potentially high / architectural | **Architecture gate**; must be resolved before claiming mature magnifier quality |
| Overview / temporary normal view | Recover orientation in a large virtual viewport | View Locator + exact temporary 1x/return | Mostly built | **Core**; preserve as a Vision strength |
| Full-screen magnification | Maximum magnified working area | Current Detail behaviour approximates this | Low | **Core** |
| Split / fixed / glass views | Mix magnified detail with unmagnified context on the same display | Not first-class; single-monitor fallback only | Moderate | **Do not assume parity**. Validate 1-2 useful forms; Context+Detail may substitute for many multi-display users |
| Hooked Areas / Freeze View | Pin clock, word count, formula bar, status, or another reference region | Reference monitor is not equivalent | Moderate | **Strong phase-2 candidate**, particularly for Excel/Office |
| Smooth panning / saved position | Reduce disorientation and repetitive manual navigation | Comfort margins / viewport policy / exact return exist | Low-moderate | **Core refinement**, likely high value |
| Application / situation settings | Different apps/tasks need different zoom, colour and tracking preferences | Global persisted settings | Moderate | **Likely phase 2**; start with simple app-specific profiles |
| Line View / Doc Reader | Reflow or isolate text for sustained reading | Not implemented | Moderate-high | **Separate reading workflow**; useful but not launch-critical until user evidence supports it |
| Multi-monitor independent zoom / colours | Make each screen usable for its role and physical size | Current architecture = one source / one Detail + optional unmanaged Reference | High | **Core architecture requirement** for Vision proposition |
| Mouse Buffer / monitor switch | Prevent accidental loss of pointer when crossing displays | Boundary policy unresolved | Low-moderate | **Raise priority**; high value relative to implementation cost |
| Clone / standard-view collaboration | Let sighted and low-vision users see same content differently | Not implemented | Moderate after generic view-session architecture | **Phase 2**, likely useful in workplace/training |
| Span | Treat several displays as one magnified canvas | Not implemented | Moderate-high | **Defer** unless user evidence shows value |
| Presentation mode | Magnified notes for presenter, ordinary slides for audience | Not implemented | Moderate after multi-view core | **Phase 2 workplace candidate** |
| Touchscreen | Direct touch exploration and zoom | Not implemented | Moderate | **Defer** for desktop-first product |
| Camera / Whiteboard | Magnify paper, remote board or another visual source | Not implemented | Moderate | **Segment-specific**, not initial office core |
| Ask AI / media ecosystem | Ancillary assistance / engagement rather than core visual access | Vision has Ask Vision concept but different purpose | Variable | **Do not let incumbent breadth drive scope** |

## Important product lesson

The evidence strengthens a `small surface, deep quality` strategy, but it changes what belongs in that small surface. The first Vision scope should not be only magnification + tracking. It should include a deliberate **orientation layer**: visible focus/caret/pointer aids, quick context recovery and predictable monitor-boundary behaviour.

That layer is particularly attractive because Vision already has POI evidence and locator rendering. The missing work is mainly product design, presets, configurability and consistency rather than inventing a new technical subsystem.
