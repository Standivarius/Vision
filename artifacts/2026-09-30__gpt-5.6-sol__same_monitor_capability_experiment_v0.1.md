# Vision same-monitor interactive magnification experiment v0.1

Date: 2026-09-30
GitHub: #22
Status: RUNNING

## Question

Does the current WGC + D3D11 path support usable interactive magnification when source and destination are the same physical monitor, or does it only support a non-recursive display window?

## Existing implementation

The current --single-monitor path:
- binds destination to the source monitor;
- creates a topmost overlapped Detail window at roughly 45% of monitor width/height;
- keeps WS_EX_NOACTIVATE;
- calls SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE) on the Detail window;
- does not install WS_EX_TRANSPARENT;
- does not implement click/drag/wheel input-coordinate translation or forwarding through the Detail window.

Therefore capture exclusion is necessary but not sufficient evidence.

## Acceptance / falsification criteria fixed before test

### A. Recursion exclusion
Pass if:
- SetWindowDisplayAffinity succeeds and GetWindowDisplayAffinity reports WDA_EXCLUDEFROMCAPTURE;
- same-monitor capture/render stays stable with zero Present failures for a bounded run;
- no evidence indicates the Detail window is being re-captured recursively.

Failure means normal WGC same-monitor support is not viable without a different presentation/capture mechanism.

### B. Interaction correspondence
First-class interactive same-monitor support requires:
- clicks inside the magnified surface act on the corresponding source point rather than the Vision window;
- drag/selection and wheel input reach the intended underlying application with source-coordinate correspondence;
- pointer representation is not duplicated or misleading.

A hit-test owned by the Vision Detail window with no remapping/forwarding path fails this gate even if recursion exclusion passes.

### C. Focus retention
A magnified view should not steal keyboard focus from the source application merely because it renders on top. WS_EX_NOACTIVATE is positive evidence but must not be confused with input correspondence.

### D. Z-order/system UI
Start, Alt+Tab, notifications, menus and elevated/secure-desktop boundaries must remain usable. These are later physical/manual checks if the basic interaction gate survives.

## Decision rule

- If A and B pass: normal WGC presenter remains a candidate for first-class same-monitor support.
- If A passes but B fails: classify current implementation as bounded/windowed viewing fallback only; first-class same-monitor support requires an explicit input-interaction design or another backend.
- If A fails: do not use current WGC same-monitor path as a product mode.

## Result

Canonical bounded run:
lab/benchmarks/integrated_app/runs/2026-09-30_23-37-50__same_monitor_capability

Observed:
- GetWindowDisplayAffinity = 0x00000011, WDA_EXCLUDEFROMCAPTURE;
- 143 rendered telemetry frames;
- zero Present failures;
- WS_EX_NOACTIVATE = true;
- WS_EX_TOPMOST = true;
- WS_EX_TRANSPARENT = false;
- foreground window was preserved across Vision startup;
- WindowFromPoint at the centre of the magnified Detail surface returned the Vision Detail HWND itself;
- hit-test class/title: VisualDetailWindow / Vision - Detail.

Repository inspection confirms the current Detail window procedure has no click/drag/wheel coordinate-remapping or input-forwarding mechanism to the underlying source application.

## Gate verdict

### A. Recursion exclusion — PASS for the bounded fallback

The current Windows 26200 / Dell environment accepts WDA_EXCLUDEFROMCAPTURE and the same-monitor WGC render loop remains stable with zero Present failures. No recursion symptom was observed in the bounded run.

This is sufficient to retain capture exclusion as a viable primitive. It is not a claim that every Windows/capture environment will honour the affinity identically; Microsoft documents SetWindowDisplayAffinity as applying to specific public OS capture mechanisms rather than as a security guarantee.

### B. Interaction correspondence — FAIL for first-class self-magnification

The magnified surface is the input hit-test owner and is not transparent. Vision currently performs no source-coordinate remapping or forwarding for click, drag, selection or wheel input.

Therefore a user cannot operate the underlying application through the magnified pixels. Testing drag/selection/wheel individually would only repeat the already-proven missing mechanism.

### C. Focus retention — PASS at startup

WS_EX_NOACTIVATE is present and foreground focus was preserved during the bounded run. This is useful for a viewer/fallback window, but it does not compensate for the failed pointer/input correspondence.

### D. Z-order/system UI/elevation — DEFERRED

Start/Alt+Tab/notifications/menus/elevated-window testing is not decision-blocking once the fundamental interaction gate has failed. Revisit only if a future same-monitor interaction design is implemented.

## Capability verdict

Current Vision WGC + D3D11 same-monitor support is:

**SUPPORTED ONLY AS A BOUNDED WINDOWED VIEWING FALLBACK; NOT FIRST-CLASS INTERACTIVE SELF-MAGNIFICATION.**

Do not advertise or architect the current full-screen/same-screen path as equivalent to Windows Magnifier, ZoomText Full/Lens or SuperNova full-screen interaction.

## What would be required to reopen first-class same-monitor support

At least one explicit interaction architecture must be prototyped and proven:

1. input remapping/forwarding from magnified coordinates to source coordinates while preserving selection, drag, wheel, hover, cursor and focus semantics; or
2. a different Windows magnification/presentation backend that preserves normal application interaction; or
3. a deliberately bounded lens/docked/contextual geometry whose non-interactive region is acceptable by product design.

Do not add WS_EX_TRANSPARENT alone and call this solved: click-through would target the physical underlying coordinate, not automatically the source coordinate represented by the magnified pixel.

## Decision

Close #22 for the current architecture with the bounded-window verdict. Reopen only when Vision intentionally prototypes one of the interaction models above.
