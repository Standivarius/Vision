# MARIUS-DELL Project Dev OpenAI tunnel autostart repair v0.1

**Date:** 2026-09-30  
**Scope:** local ChatGPT/OpenAI project-dev bridge startup reliability on MARIUS-DELL  
**Bridge root:** C:\mcp\project-dev  
**Tunnel profile:** project-dev-dell

## Problem observed

After Windows restart, Local Project Dev – Dell initially appeared unavailable. Manual recovery through the ProjectDevDellTunnel scheduled task restored access.

Inspection found the startup design had drifted:

- the resilient supervisor existed at C:\mcp\project-dev\start-tunnel-resilient.ps1;
- the Windows Startup fallback was absent from the real user Startup folder;
- run-silent.vbs still called the older one-shot start-tunnel.ps1 rather than the resilient supervisor;
- the bridge therefore depended too heavily on the scheduled-task path.

## Repair

The following host-level changes were made without changing the Vision repo implementation:

1. Backed up run-silent.vbs and register-startup.ps1.
2. Backed up start-tunnel-resilient.ps1 before modification.
3. Changed run-silent.vbs to launch start-tunnel-resilient.ps1.
4. Restored ProjectDevDellTunnel.lnk into the DELL user Startup folder.
5. Added a named mutex to start-tunnel-resilient.ps1:
   - Local\ProjectDevDellTunnelSupervisor
   - purpose: prevent the scheduled task and Startup fallback from creating two competing supervisors.
6. Replaced the old pre-mutex supervisor with the hardened supervisor.
7. Launched the Startup path redundantly as a test; process inspection showed exactly:
   - one resilient supervisor;
   - one project-dev-dell tunnel-client.

## Reboot validation

On the later 2026-09-30 reboot:

- Windows boot time: 12:41:26;
- resilient supervisor creation: 12:42:05;
- tunnel-client creation: 12:43:18;
- supervisor parent: svchost.exe, consistent with the Windows Task Scheduler launch path.

Therefore the automated scheduled-task path did start after reboot. The early ChatGPT probe occurred before the tunnel had become usable and was initially mistaken for a startup failure.

Operational conclusion:

**Allow roughly 1–2 minutes after Windows login/reboot before declaring Local Project Dev – Dell autostart failed.**

The restored Startup shortcut remains a redundant fallback. This reboot proved the scheduled-task path, not the fallback shortcut specifically.

## Tool binding clarification

Local PowerShell Dev is available but currently attached to ASUS-DESKTOP-HOME, not MARIUS-DELL.

For Vision on Dell:

- Local Project Dev – Dell is the primary repo/local-development MCP.
- Remote Desktop Commander is recovery-only.
- Local PowerShell Dev should not be treated as a Dell tool unless its host binding is explicitly changed.

## Recovery procedure if the bridge is genuinely absent after the normal startup window

Run locally on MARIUS-DELL:

SCHTASKS /Run /TN "ProjectDevDellTunnel"

Then wait for the OpenAI tunnel client to reconnect before retrying project_start("vision").

Do not substitute a Tailscale path for the OpenAI/ChatGPT tunnel. Tailscale host reachability is independent of this bridge transport.
