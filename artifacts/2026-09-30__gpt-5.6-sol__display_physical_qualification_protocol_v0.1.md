# Vision combined display identity/lifecycle/recovery physical qualification protocol v0.1

Date: 2026-09-30
Covers GitHub: #11, #13, #14
Status: READY FOR OWNER-AT-DELL SESSION

## Purpose

Use one controlled physical session to collect three kinds of evidence from the same topology changes:

1. #11 — whether display identity remains stable and where it becomes ambiguous;
2. #13 — actual Windows event ordering/timing and whether the current 500 ms debounce is adequate;
3. #14 — whether Vision rebuilds in-process and returns to the intended workspace without stale-generation movement or wrong-monitor binding.

Do not run three separate physical campaigns.

## Pre-session

Automated before touching hardware:
- record git HEAD/current build;
- save exact Vision settings copy;
- run diagnostics/topology snapshot;
- record QueryDisplayConfig identity/path evidence;
- start lifecycle telemetry/harness;
- confirm canonical two-screen baseline passes.

## Physical action sequence

Run one action at a time and wait for stable recovery before the next.

### 1. Lock / unlock
Owner locks and unlocks Windows normally.

Observe:
- display/lifecycle events;
- whether topology generation changes;
- whether capture/session recovers;
- whether monitor binding changes.

### 2. Secondary display power sleep / wake
Use monitor power/sleep control if available without cable changes.

Observe event burst and recovery timing.

### 3. Secondary cable disconnect / reconnect
Disconnect only the non-primary display first.

Measure:
- event count/order/time span;
- time until topology stops changing;
- Vision process survival;
- workspace generation transition;
- fallback state while display absent;
- restoration after reconnect;
- whether saved intent remains unchanged;
- whether Detail ever binds to the wrong display.

### 4. Primary-display designation change and restore
Use Windows Display Settings with owner present.

Record identity and geometry separately. Geometry must not be treated as durable identity.

### 5. Resolution change and restore
Change one display to a different supported resolution, then restore.

### 6. Scaling/DPI change and restore
Change one display scaling once, then restore.

This is disruptive and should be skipped if the owner is doing real work or if Windows requires sign-out.

### 7. Port swap / reboot — separate durability sub-session
Only if physically practical:
- reboot with same cabling;
- later, swap display port/cable positions if the hardware permits.

This is the strongest #11 durable-identity evidence and should not be improvised if cabling is awkward.

## Pass / fail rules

### #13 lifecycle/debounce
500 ms remains acceptable only if every observed event burst settles inside the window with no late topology event that invalidates a just-rebuilt generation. Otherwise set debounce from evidence rather than preference.

### #14 topology reconciliation
Pass each supported action only if:
- Vision process survives;
- stale generation cannot move the rebuilt workspace;
- supported topology becomes usable again without manual relaunch;
- saved workspace intent is unchanged by temporary absence;
- no ambiguous identity is silently rebound to the wrong monitor.

### #11 identity
A display identity candidate is accepted only to the extent that the same physical display can be distinguished across the tested mutation. Geometry is supporting evidence, never identity truth.

## Stop conditions

Stop the session rather than layering more changes if:
- Windows does not restore the original display configuration cleanly;
- Vision binds to the wrong display;
- the owner cannot see/use the machine comfortably;
- a system setting requests sign-out/reboot unexpectedly;
- identity becomes ambiguous and further actions could overwrite intent.

## Session output

One artifact should contain:
- before/after topology snapshots;
- raw event timeline;
- identity fields;
- Vision generation/recovery markers;
- measured quiet-window timing;
- settings checksum before/after;
- pass/fail per action;
- recommendation for #11, #13 and #14 separately.
