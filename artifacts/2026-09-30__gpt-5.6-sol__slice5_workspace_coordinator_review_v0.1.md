# Vision Structural Slice 5 architecture checkpoint v0.1

**Date:** 2026-09-30
**Result:** PASS

## Result
The current validated one-source/one-output product now runs through an explicit one-session workspace coordinator without introducing multi-view behaviour.

### Explicit objects
- `WorkspaceCoordinator`: workspace identity, topology generation reference, selected command target, movement owner, evidence-routing target and movement permission.
- `ViewSessionState`: stable ViewId plus resolved source/destination binding and movement-enabled state.
- Existing `ViewUpdateStep` continues to own viewport/return transition state.
- Existing `EvidenceSampler` continues to sample global pointer/caret/focus evidence once per update.
- Slice 4 objects retain graphics ownership: `GpuDeviceDomain`, `CaptureSource`, `OutputPresenter`, `Renderer`.

## Architecture checkpoint: ownership questions
1. **Where is evidence sampled?** EvidenceSampler, once per current capture/update loop.
2. **Where is evidence routed?** WorkspaceCoordinator. For the current one-view workspace it routes to Detail view 1.
3. **Where is movement permission decided?** WorkspaceCoordinator via movement-owner + per-session movement-enabled state.
4. **Where is viewport/return state?** ViewUpdateStep/ViewController path for the owning ViewSession. No second session exists yet.
5. **Where is capture lifetime?** CaptureSource + WGC CaptureRunner, using GpuDeviceDomain.
6. **Where is presentation lifetime?** OutputPresenter; Renderer owns shader/render resources, not swapchain lifetime.
7. **Where is topology state?** Current physical enumeration remains startup-owned; WorkspaceCoordinator carries a topology-generation reference. Durable MonitorRegistry/topology ownership is intentionally Slice 6.

## Behaviour preservation
The one current ViewSession is bound to the resolved Context source and Detail destination. It is both selected command target and sole movement owner. Therefore evidence reaches the same ViewUpdateStep as before.

Telemetry now records:
- workspace_1_topology_generation_1
- view_selected_detail_1
- movement_owner_detail_1

No ownership-transfer policy has been introduced.
