## 2. Architecture & Execution Flow

The test farm follows the required six-stage pipeline:

```
[Scenario Catalogue]
       │
       ▼
[Planner / Resolver]  ──(Preflights capabilities)──► RUNNABLE / SKIPPED / BLOCKED / INVALID
       │
       ▼
[Isolated Execution]  ──(Desktop lock + Settings backup + WinSta0\Default routing)
       │
       ▼
[Evidence Bundle]     ──(scenario.resolved.json, environment.json, events.jsonl, assertions.json, result.json, SUMMARY.md)
       │
       ▼
[Deterministic Oracle]──(Evaluates assertions: exit_code, metrics, regex, geometry delta)
       │
       ▼
[Aggregator & Queue]  ──(Clusters failure signatures; compiles review queue; aggregate.json + AGGREGATE.md)
```

### Critical Windows Integration Discovery
When automated runners execute from non-interactive or sandbox desktops (e.g. `exebox-...`), DWM marks DXGI swapchains as occluded (`DXGI_STATUS_OCCLUDED` = `0x087A0001` = `142213121`).  
The runner resolves this by launching interactive scenarios via Win32 `CreateProcessW` with `STARTUPINFOW.lpDesktop = L"WinSta0\\Default"`, ensuring interactive instances bind directly to the active user console display.

### Root Cause Analysis of Real Vision Failures
Inspection of the six failing scenarios revealed an identical root cause:
- **Observed fact:** In the active production refactoring of `app/src/main.cpp` (lines 1070–1119), `WindowProc` does not have a `case WM_CLOSE:` handler.
- **Consequence:** The window class is `WS_POPUP` with `WS_EX_APPWINDOW | WS_EX_NOACTIVATE`. `DefWindowProcW` ignores `WM_CLOSE` on popups without `WS_SYSMENU`.
- **Impact on tests:** `run-arbitration-smoke.ps1`, `run-caret-smoke.ps1`, `run-focus-smoke.ps1`, and `run-pointer-stress-smoke.ps1` exit via `PostMessage(0x0010)` (`WM_CLOSE`). Because `WM_CLOSE` is ignored, `WaitForExit(5000)` times out, causing the smoke script to report failure (`Visual did not close`).
- **Confirmation:** When tests exit via `Ctrl+Alt+Q` (`kHotkeyExit` -> `DestroyWindow(hwnd)`), such as `lifecycle_smoke`, `exact_return`, and `mouse_viewport_smoke`, they exit instantly and PASS.
- **Rule compliance:** Per assignment instructions, production code in `app/src/main.cpp` was **not modified** to make harness tests pass. Real failures were accurately preserved and clustered.
