# Vision Windows Magnifier and formative user evidence protocol v0.1

Date: 2026-09-30
GitHub: #21
Status: READY FOR HUMAN SESSION

## Purpose

Test whether Vision's focused product wedge produces useful task-level advantages over the free Windows Magnifier baseline, and identify defaults/features that should change before broader alpha.

This is not a feature-parity test and not a benchmark race.

## Comparison boundary

Windows Magnifier:
- use its normal full-screen workflow as the free baseline;
- do not force it into an artificial multi-monitor imitation of Vision.

Vision:
- use the current two-monitor Context + Detail workflow;
- current same-monitor mode is excluded from this comparison because #22 found it is only a bounded non-interactive viewing fallback.

Compare the user's task outcome and orientation cost, not identical window geometry.

## Session stages

### Stage 0 — owner/debug session

Purpose: debug instructions and instrumentation, not infer low-vision product value.

Tasks:
1. Word document editing at a real working zoom.
2. Browser form/text editing in a currently compatible workflow.
3. Excel navigation/formula inspection when no real user workbook is open.
4. temporary 1x inspect and exact return.
5. deliberate loss-of-place/recovery task.
6. app switch and return.

Capture:
- task completion;
- number of explicit recovery/recentre actions;
- obvious wrong-target or lost-context episodes;
- manual panning/repositioning;
- qualitative text-quality notes;
- which behaviour was surprising or required explanation.

### Stage 1 — formative low-vision / assessor sessions

Use the same core tasks but let participants choose their real working zoom and normal Windows text/display settings.

Do not collect medical diagnosis unless independently required for the study. Record only task-relevant context:
- habitual magnifier/product;
- typical zoom range;
- number of displays normally used;
- whether participant normally follows pointer, caret or focus;
- applications central to their work.

## Core tasks

### A. Orientation and recovery
Navigate away from the current point of work, then recover:
- where am I?
- what area is magnified?
- can I get back to the previous working position?

### B. Word editing
- find a paragraph;
- edit inside a long line;
- move caret vertically;
- use one ribbon/control;
- return to text.

### C. Browser work
- navigate a form or ordinary edit control;
- type and correct text;
- move between page control and text entry;
- recover after viewport movement.

Use only a browser/editor combination currently supported by the compatibility ledger. Current Edge 154 textarea semantic-caret regression must be resolved or explicitly excluded before this task is used as a Vision success claim.

### D. Excel
- move across cells;
- inspect row/column context;
- edit a value or formula;
- move between cell and formula bar.

### E. Temporary inspect / return
At magnified working zoom:
- invoke 1x inspection;
- locate global context;
- return to the exact prior magnified position.

### F. Cross-application return
Move to another application and back; assess whether the user can resume without re-orienting from scratch.

## Observations to record

Use event counts and short notes, not pseudo-precision:
- completed / blocked / abandoned;
- recovery/recentre actions;
- unintended viewport moves;
- moments the user asks or visibly needs to determine location;
- pointer/caret/focus tracking failure;
- locator usefulness;
- text-quality complaint;
- task-specific preference and why;
- support/explanation needed.

Optional 1–5 ratings after each task:
- orientation confidence;
- visual comfort;
- predictability;
- effort.

Do not aggregate these into a single 'winner' score. The purpose is to identify where each workflow succeeds or fails and what should change in Vision.

## Evidence that can change product decisions

Escalate when:
- the same recovery/orientation failure appears in more than one participant/task;
- users repeatedly disable or fight an automatic behaviour;
- Context + Detail is not understood after minimal explanation;
- Windows Magnifier is materially easier for a core task Vision is meant to improve;
- Vision's locator/inspect-return materially reduces recovery effort;
- a compatibility problem blocks a normal workplace task;
- the final shortcut model causes discoverability or keyboard-layout friction.

## Exit condition for #21 first tranche

Enough evidence for the next Opus/Astra review gate when:
- owner/debug session is complete;
- at least the first genuine low-vision or assessor session is recorded;
- Windows Magnifier has been exercised on the same core task set;
- resulting changes/default hypotheses are explicit, including negative evidence.

A larger user study is not required before the review gate.
