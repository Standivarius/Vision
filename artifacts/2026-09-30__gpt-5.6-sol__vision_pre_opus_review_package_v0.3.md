## What changed from v0.1

The hands-on work was widened from a narrow pointer/caret/focus benchmark into feature discovery.

The major correction is that visual locator/highlighting is now first-product core rather than late polish. The proposed architecture therefore separates POI/viewport policy from visual-overlay policy.

Alternative view geometry is also treated more seriously: Vision should not copy every incumbent mode, but the architecture should preserve a clean path to one non-full contextual/lens/fixed view.

The common Vision/ZoomText/SuperNova workload baseline is now available, and SuperNova Magnifier 25.05 was installed and its actual menu feature tree captured.

## Evidence boundary

Validated hands-on:
- common pointer/caret/focus/cross-monitor bench for Vision and SuperNova, and useful canonical/raw ZoomText evidence;
- ZoomText 40-minute-mode launch, zoom stepping and temporary-1x/return;
- SuperNova Magnifier 25.05 installed product/edition and full installed menu tree;
- current two-monitor Dell topology;
- comparative process/resource sampling.

Current official vendor evidence fills feature semantics that the automation session could not safely verify by changing every setting.

Not yet controlled well enough to claim:
- matched Office rendering quality for Vision versus xFont/TrueFonts at the same exact zoom;
- subjective low-vision preference between full-screen, Context+Detail and lens/fixed alternatives;
- real-task value of Freeze View / Hooked Areas;
- physical 3/4-monitor usability.

These gaps are now explicit. The first is tracked separately in GitHub Project #6 as the Office text-quality decision experiment. Opus should decide whether it must precede architecture extraction or can gate only the later renderer decision.
